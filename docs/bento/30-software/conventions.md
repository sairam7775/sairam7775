# Code conventions

- **Every word a page shows lives in `bento/src/copy/en.ts`** (`import { copy } from "@/copy"`). No text in components, actions or error helpers.
  - A sentence with a value in it is a function, so word order stays in the file.
  - A test refuses empty lines and internal words (such as "stub" or "tier").
  - Not in it: Bento Man's prompt (instructions to the model) and place data (the database).
  - A second language would be another file satisfying the same `Copy` type.
- **The planner's sentences** (reasons, left-out details, warnings, gap cards, route arithmetic, date refusals) are in `copy.plan`, a plain module the engine can import, so the engine stays free of frameworks.
- **Server components by default;** `"use client"` only where interaction needs it.
- **Server actions for changes,** with input checked by Zod at the boundary.
- **Design tokens, not raw colours:** Tailwind v4 theme tokens in `globals.css` (`text-ink-2`, `bg-surface`, `border-rule`). See [design](../20-design/README.md).
- **The logo** is `bento/src/components/logo.tsx`; every PNG is generated by `scripts/render-icons.mjs`; never hand-edit a raster ([logo](../20-design/logo.md)).
- **`npm run typecheck`** runs `next typegen` first: Next 16's page and layout prop types are generated, so bare `tsc` fails on a clean checkout.
- **Next.js 16 differs from older versions:** read the guide in `node_modules/next/dist/docs/` before writing Next-specific code.
- Server setup problems (a missing key) are logged with the variable's name; the traveller gets plain words.
